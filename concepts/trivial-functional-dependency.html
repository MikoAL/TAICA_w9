trivial functional dependency（平凡函數相依）

動機

想把 orders(order_no, shop, shop_phone, item) 上 holds 的 functional dependency 全部列出來，馬上會冒出一大堆像 {shop, item} → shop 這樣的規則。它們永遠成立，卻沒告訴我們任何關於店家或訂單的事。

這種規則需要一個名字，才能在列清單、判斷正規化時把它們挑出來放一邊。

從已知出發

先複習：satisfy

instance r satisfy α → β，是指 r 裡任兩個 tuple 若在 α 上相同，就在 β 上相同。（functional dependency 頁）

假設 β 的每個 attribute 都在 α 裡。兩個 tuple 在 α 上相同，意思是在 α 的每一個 attribute 上都相同，其中當然包括 β 的那些 attribute。

所以「右邊相同」是「左邊相同」直接附帶的結果，不需要任何現實規則幫忙。任何 relation 的任何 instance 都 satisfy 它，因此它在每個 schema 上都 holds。

正式定義

trivial functional dependency

若 β ⊆ α，則 α → β 是 trivial functional dependency（平凡函數相依）。判斷只看 attribute 的名字，不看任何資料。

nontrivial functional dependency

β 只要有一個 attribute 不在 α 裡，α → β 就是 nontrivial functional dependency（非平凡函數相依），也就是 β ⊄ α。

例子

例 1：同一個左邊，一條 trivial、一條不是

在 ticket(venue, seat, show_date, holder) 上：

  • {venue, seat} → venue 是 trivial：{venue} ⊆ {venue, seat}。
  • {venue, seat} → {seat, show_date} 不是 trivial，雖然右邊的 seat 也出現在左邊。show_date 不在左邊，所以 β ⊄ α。

第二條要判斷它 holds 與否，就得回到現實規則；第一條不用。

考試提醒

題目要求「列出 nontrivial functional dependency」時，右邊只要有一個 attribute 不在左邊就要留下，左右有重疊不代表 trivial。

自我檢測

R(A, B, C)。下列哪些是 trivial functional dependency？

  1. A → A
  2. {A, B} → {B, C}
  3. A → ∅
看答案
  1. trivial：{A} ⊆ {A}。左右完全相同是 β ⊆ α 最簡單的情況。
  2. 不是：C ∉ {A, B}。
  3. trivial：空集合是任何集合的子集。兩個 tuple 在 ∅ 上的值一定相同，所以它永遠被 satisfy。

最容易錯的是第 2 題，看到 B 重疊就判成 trivial。避免的方法是逐一檢查右邊每個 attribute 是否都在左邊。
