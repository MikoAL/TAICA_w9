練習：從 instance 判斷 functional dependency

題目

外送平台的派送紀錄如下，每一列是一筆訂單。

delivery(order_no, rider, zone, fee)
order_noriderzonefee
t₁D101阿傑東區40
t₂D102小芳西區55
t₃D103阿傑西區55
t₄D104小芳西區55
t₅D105阿明南區40
  1. 這份 instance satisfy 下列哪些 functional dependency？（a）zone → fee（b）rider → zone（c）{rider, zone} → fee（d）fee → zone
  2. 平台規定「運費只依區域決定」。zone → fee 在 delivery 上 holds 嗎？只根據這份 instance 能下這個結論嗎？

題目來源：原創練習題

這題在考什麼

考的是 functional dependency 的 satisfy 與 holds。第 1 小題問「這份 instance satisfy 哪些」，是逐對檢查資料；第 2 小題問「holds 嗎」「只根據 instance 能不能下結論」，是在測你分不分得清這兩個詞。

先複習

先複習：satisfy 與 holds

instance r satisfy α → β：r 裡任兩個 tuple 若在 α 上相同，就在 β 上相同。α → β holds：每一個 legal instance（遵守現實規則的任何一份資料）都 satisfy 它。（functional dependency 頁）

解題

方法：依左邊分組，只看有兩列以上的組

要推翻 α → β，需要一對在 α 上相同的 tuple。所以先把資料依 α 的值分組：只有一列的組不可能出問題，直接跳過。剩下的組裡，檢查 β 的值是否全部相同。

（a）zone → fee：satisfy

依 zone 分組：東區只有 t₁，南區只有 t₅，西區有 t₂、t₃、t₄。西區三列的 fee 都是 55，沒有反例。

（b）rider → zone：不 satisfy

阿傑出現在 t₁ 和 t₃，zone 分別是東區和西區。找到這一對就可以停了，不必再看小芳。

（c）{rider, zone} → fee：satisfy

這裡分組要看 rider 和 zone 兩個都相同。t₁（阿傑, 東區）和 t₃（阿傑, 西區）不同組，因為 zone 不同；唯一有兩列的組是 t₂ 和 t₄（小芳, 西區），fee 都是 55。

其實可以不檢查：（a）已經 satisfy。在 {rider, zone} 上相同的兩列，在 zone 上一定也相同，所以 fee 也相同。左邊多加 attribute，要比的對只會變少。

（d）fee → zone：不 satisfy

方向反過來，分組改看 fee。fee = 40 的有 t₁（東區）和 t₅（南區），zone 不同。（a）satisfy 不代表反方向也 satisfy。

第 2 小題：holds，但不是從 instance 看出來的

平台規定運費只依區域決定，所以每一個 legal instance 裡，同區的兩筆訂單運費都相同：zone → fee holds。

只根據這份 instance 則不能下結論。instance 沒有反例，只代表「到目前為止沒被推翻」。如果平台沒有這條規定，明天就可能出現一筆西區 60 元的訂單，那份資料一樣是 legal instance。

答案：第 1 小題 satisfy 的是（a）和（c）；（b）的反例是 t₁、t₃，（d）的反例是 t₁、t₅。第 2 小題 holds，理由是平台規定，不是這份資料。

陷阱

最常見的錯誤答案是第 2 小題寫「從表中可以看出 zone 相同時 fee 都相同，所以 holds」。這把 satisfy 當成了 holds：資料只能推翻規則，證明 holds 一定要靠現實規則。

第二個陷阱在（d）：看到（a）成立就順手把（d）也勾起來。functional dependency 有方向，反過來要重新檢查。

變化題

把 t₄ 的 fee 從 55 改成 60，其他不變。第 1 小題（a）到（d）的答案哪些會改變？為什麼（a）和（c）會一起變？

看答案

（a）和（c）從 satisfy 變成不 satisfy；（b）和（d）原本就不 satisfy，反例 t₁、t₃ 和 t₁、t₅ 都沒動到。

  • （a）zone → fee：西區的 t₂（55）和 t₄（60），t₃（55）和 t₄（60），都是反例。
  • （c）{rider, zone} → fee：t₂ 和 t₄ 都是（小芳, 西區），fee 是 55 和 60。

一起變是因為 t₂、t₄ 這一對在 {rider, zone} 上相同，在 zone 上當然也相同，所以它同時推翻兩條。反過來不一定：t₃、t₄ 推翻（a），卻不推翻（c），因為它們的 rider 不同。

最容易錯的是以為（c）不受影響，因為「只有一列被改」。避免的方法是照分組法重做一次，不要沿用舊答案。
